# SmartRoute Admin – פאנל ניהול

אתר סטטי לניהול המשתמשים של **SmartRoute** (הנתונים ב-`labUsers/{uid}`), באותו פרויקט Firebase (`smartrun-gbit`). **SmartRun** נשמר כארכיון ואינו מוצג כאן.

| מסך | מה יש בו |
|---|---|
| 📊 **סקירה** | כל המשתמשים ביום, בשבוע או בחודש (עם ← → למעבר בין תקופות): משלוחים, נמסרו, לא ענה, נשארו, אחוז השלמה ושעות עבודה |
| 👥 **משתמשים** | רשימה עם חיפוש, תפקיד, מצב פעיל/מושבת, מי הזמין, התקדמות היום, מתי נראה לאחרונה, מיקום אחרון, לידים ו**השבתה/הפעלה** |
| 👤 **משתמש** | פרטים, תפקיד, מי הזמין ואת מי הזמין, קישורי ההרשמה (Ref) שלו ומיקום אחרון. יום עבודה חי: מפה עם העצירות, המסלול שתוכנן והמסלול בפועל. רשימות "בוצעו" (לפי שעה) ו"נשארו" (לפי סדר המסלול). בשבוע ובחודש: גרף לפי יום וטבלת ימי עבודה |
| 📝 **הרשמות** | פניות מטופס ההרשמה, עם סטטוס (חדש, נוצר קשר, הצטרף, לא רלוונטי), הערה ומי הפנה (לפי ה-Ref). **💬 שלח קישור** פותח וואטסאפ לפונה עם קישור ההצטרפות שלך |
| 🔗 **קישורים** | קישור ההצטרפות (Magic Link) שלך: העתקה, וואטסאפ, יצירת קישור חדש. המנהל הראשי רואה את הקישורים של כל המנהלים |

`?demo=1` בכתובת = נתונים לדוגמה, בלי חיבור לענן. `?demo=1&as=admin` = אותו דבר, בתצוגה של מנהל רגיל.

## תפקידים
| | מנהל ראשי (SUPERADMIN) | מנהל (ADMIN) | משתמש |
|---|---|---|---|
| מי | רק `gbitman.bd@gmail.com`. מוגדר בכללים (`isSuper()`), ואי אפשר לתת את התפקיד הזה | מי שהמנהל הראשי מינה | כל מי שהצטרף דרך קישור הזמנה |
| פאנל הניהול | ✓ | ✓ | ✗ אין גישה בכלל |
| מינוי מנהל / החזרה למשתמש | ✓ | ✗ | ✗ |
| השבתת משתמשים | כולם, חוץ ממנו עצמו | משתמשים רגילים בלבד | ✗ |
| מחיקת משתמשים (כולל נתוני העבודה, לפי בחירה) | ✓ כולם, חוץ ממנו עצמו | ✗ | ✗ |
| קישורי הצטרפות | רואה את כולם ויוצר לכל מנהל | רואה רק את שלו | ✗ |
| Ref מותאם (לבדיקות A/B) | מוסיף לכל משתמש, ומכבה ומפעיל | ✗ | ✗ |

## הצטרפות ל-SmartRoute
1. אדם ממלא את **טופס ההרשמה** (`…/smartroute/Registration`) עם שם, נייד ו-Ref. הקישור `…/Registration?ref=gil-d87d32` ממלא את ה-Ref מראש ונועל אותו.
2. הפנייה מופיעה ב-**📝 הרשמות**. המנהל מדבר עם הפונה ושולח לו את **קישור ההצטרפות** שלו (`…/smartroute/?invite=…`).
3. הפונה נכנס עם Google דרך הקישור ומצטרף. המשתמש החדש נרשם על שם **בעל הקישור** (`members/{uid}.invitedBy`).
4. מי שמתחבר בלי קישור מקבל **"המשתמש לא קיים"** ומופנה לטופס ההרשמה.
- כל מי שיש לו את קישור ההצטרפות יכול להירשם. **🔄 קישור חדש** מכבה את הקישור הישן.
- **Ref אישי:** כל משתמש יוצר ב-SmartRoute (☰ ← הזמן חבר) שני קישורי הרשמה שעובדים שניהם, עם אותה סיומת אקראית: לפי אימייל (`gbitman.bd-d87d32`) ולפי שם (`gil-d87d32`). הוא בוחר איזה מהם ראשי. הפאנל סופר לידים לכל Ref.

## מבנה הנתונים (Firestore)
- `members/{uid}`: `role` (`user`/`admin`), `disabled`, `invitedBy`, `inviteToken`, `refSuffix`, `primaryRef`.
- `invites/{token}`: קישורי הצטרפות. `owner`, `active`.
- `refs/{ref}`: קודי הפניה. `owner`, `kind` (`email`/`name`/`custom`), `label`, `active`, `leads`.
- `registrations/{id}`: פניות מהטופס. `name`, `mobile`, `ref`, `source`, `status`, `note`.
- `labUsers/{uid}`: פרופיל ונתוני העבודה ב-SmartRoute (מיקום אחרון, ימים, משלוחים).

כל ההרשאות נאכפות ב-`firestore.rules`. הטופס הציבורי יכול רק ליצור פנייה, בשדות מאומתים.

## פריסה
1. **כללי Firestore:** `firestore.rules` נמצא ב-SmartRoute (ועותק זהה ב-SmartRun). הפריסה מתיקיית `SmartRoute`:
   ```bash
   npx -y firebase-tools@latest deploy --only firestore:rules --project smartrun-gbit
   ```
2. **האתר:** GitHub Pages מה-repo `Gbitman84/smartroute-admin`, בכתובת https://gbitman84.github.io/smartroute-admin/. הדומיין `gbitman84.github.io` כבר מאושר ב-Firebase Auth.
