# SmartRoute Admin – פאנל ניהול

אתר סטטי לניהול המשתמשים של **SmartRoute** (הנתונים ב-`labUsers/{uid}`), באותו פרויקט Firebase (`smartrun-gbit`). **SmartRun** נשמר כארכיון ואינו מוצג כאן.

| מסך | מה יש בו |
|---|---|
| 📊 **סקירה** | כל המשתמשים ביום, בשבוע או בחודש (עם ← → למעבר בין תקופות): משלוחים, נמסרו, לא ענה, נשארו, אחוז השלמה ושעות עבודה |
| 👥 **משתמשים** | רשימה עם חיפוש, מצב פעיל/מושבת, התקדמות היום, מתי נראה לאחרונה, מיקום אחרון ו**השבתה/הפעלה** |
| 👤 **משתמש** | פרטים, מיקום אחרון ויום עבודה חי: מפה עם העצירות, המסלול שתוכנן והמסלול בפועל. רשימות "בוצעו" (לפי שעה) ו"נשארו" (לפי סדר המסלול). בשבוע ובחודש: גרף לפי יום וטבלת ימי עבודה |

`?demo=1` בכתובת = נתונים לדוגמה, בלי חיבור לענן.

## איך זה עובד
- **מי מנהל:** רק `gbitman.bd@gmail.com`. הרשימה מוגדרת ב-`firestore.rules` (`isAdmin()`), ובנוסף ב-`js/config.js` לתצוגה בלבד. ההרשאה נאכפת בכללים.
- **השבתה:** המסמך `access/{uid}` מקבל `disabled: true`. הכללים חוסמים את המשתמש מהנתונים שלו, והאפליקציה מציגה "החשבון הושבת". הנתונים לא נמחקים. בהפעלה מחדש האפליקציה נטענת שוב אוטומטית.
- **מה SmartRoute שולח:**
  - בכל כניסה: פרופיל (`labUsers/{uid}`) עם שם, אימייל, תמונה, "נראה לאחרונה" ו"משתמש מאז".
  - המיקום האחרון, רק כשהאפליקציה כבר מאתרת: ברענון מיקום, בבניית מסלול ובעדכון סטטוס. לכל היותר פעם בדקה, בלי מעקב רציף.
  - בכל עדכון סטטוס: המיקום שבו הסטטוס נקבע (משמש ל"מסלול בפועל").
  - ביום העבודה: סיכום `stats` (נמסרו, לא ענה, נשארו, שעת משלוח ראשון ואחרון).
- **ימים ישנים** (לפני העדכון) אין להם `stats`, והפאנל מחשב אותם מהמשלוחים עצמם.
- **משתמש מופיע ברשימה** רק אחרי שנכנס ל-SmartRoute בגרסה המעודכנת.

## פריסה
1. **כללי Firestore:** `firestore.rules` נמצא ב-SmartRoute (ועותק זהה ב-SmartRun). הפריסה מתיקיית `SmartRoute`:
   ```bash
   npx -y firebase-tools@latest deploy --only firestore:rules --project smartrun-gbit
   ```
2. **האתר:** GitHub Pages מה-repo `Gbitman84/smartroute-admin`, בכתובת https://gbitman84.github.io/smartroute-admin/. הדומיין `gbitman84.github.io` כבר מאושר ב-Firebase Auth.
